# DC #313 — Authoritative shared HMAC key and timestamp boundaries

Operator decisions: only `https://chatgpt.com` is supported.  New key
records use origin-scoped IndexedDB and a native exclusive Web Lock.
The operator permits page-origin access to the 256-bit key.  Raw key bytes
must not enter GEN/COMM recordings, debug JSON, metadata, URLs or exports.

## Breaking protocol decision (2026-10-22)

The legacy ephemeral V1 secret-marker format, decoder, test fixtures and
recording compatibility are **RETIRED**, regardless of historical merge
state.  The operator intends to discard old experimental recordings.
This does not remove the live recorder's unrelated credential-sanitizing
fallback.  Historical predecessor issue evidence remains on GitHub, but
is not a new release acceptance criterion.

No independent random nonsecret key-generation ID is permitted.  The only
public generation identity is `key_restart`: the ISO 8601 UTC timestamp
derived from the key record's persisted `issued_at_ms`.  It is never
independently generated by a tab or stream writer.

- Initial creation sets `issued_at_ms` once under the shared lock.
- Confirmed manual Randomize, scheduled expiry and overdue startup make a
  different key with an activation time strictly later than the previous
  `issued_at_ms`, even if both occur in the same wall-clock millisecond.
- Ordinary tab or browser reloads reuse the key and timestamp unchanged.
- Each new key draws an independent due time 23–25 hours later.
- During draining, the old key/timestamp remain authoritative for all
  already admitted work; no next-generation event or new admission until
  verified pending work finishes.
- All shared lifecycle records are atomic and fail closed on unavailable
  storage, corruption, inconsistent readback or unreconciled admissions.

The new storage database is `downloadconversation-persistent-hmac-v3`
with record format `dc-secret-key-record/3`, isolating it from previous
experimental generation-ID records without silently migrating them.

## Recording boundaries (downstream writer contract)

GEN and COMM consume the SAME committed `key_restart` value from the
authoritative lifecycle service, never their own local `Date.now()` or
per-fragment creation time.

**COMM:** Every new fragment's metadata header has both `version` and
`key_restart` before any event/body rows.  A late-created fragment within
one key cycle repeats its original `key_restart` unchanged.

**GEN:** A key-boundary `key_restart` entry appears alongside the initial
`version` information at the start of the key-generation segment, before
any generation content.

When the key changes, writers close/seal the current key-bound segment
and begin a new one with the new timestamp.  Pending old-key records may
finish only under their originally admitted key and original timestamp.
Incomplete/failed records carry explicit provenance; they cannot silently
move to a newer generation.

The durable nonsecret `hmac-key-cycle` journal uses
`hmac-key-cycle:<key_restart>` as stable idempotency ID and includes
`key_restart`, `epoch`, `occurred_at_ms` and `reason` (`initial`,
`manual`, `scheduled` or `overdue`).  This is an internal event source
for both GEN and COMM; actual disk emission remains the responsibility
of their corresponding writer owners.

The internal `epoch` is an ordered journal/replay index, **not** another
random generation label or identifier stored in the log header.  No
additional public key generation token may be emitted.

## Verification boundaries

DC #313 owns source lifecycle correctness, timestamp uniqueness,
first-use races, expiry, safe draining, persistence and the event-source
contract.  Distinct actual installed-browser tests must cover the new
timestamp schema; v0.1.4 tests based on random IDs are historical only.

DC #317 owns physical COMM Worker file emission and terminal receipts.
DC #318 owns confirmed Randomize control and producer wiring.
DC #319 owns independent final candidate assembly with exact GEN/COMM
fragment/header disk readback and correlation, including restart/replay,
incomplete writes and no mixed-generation fragment.

Passing a synthetic journal equality assertion does not prove that
either physical recording stream contains a durable `key_restart`.
No merge without the user's explicit authorization.
